# Coding Standards

These standards apply to code written or modified in this repository. A more specific directory-level `CODING_STANDARDS.md` overrides conflicting rules here; nonconflicting rules continue to apply.

## Human Readability and Commenting Hygiene

- Write code for human understanding: use meaningful names, straightforward structure, and clear control flow.
- Use comments to explain **why** code behaves a certain way, especially non-obvious intent, constraints, invariants, tradeoffs, and workarounds.
- Explain surprising behavior or complex logic where a maintainer otherwise would need to reconstruct the reasoning.
- Avoid comments that merely restate obvious operations or compensate for unclear code.
- Keep comments accurate when editing related code; remove obsolete, misleading, and redundant comments.
- Keep documentation concise and near the code or decision it explains when practical.

Good commenting hygiene means useful, accurate context—not a high volume of comments.
