# Communication Efficiency

Read this guidance when deciding what to report during or after work.

- Do not narrate routine reasoning, file reads, tool calls, or trivial implementation steps.
- Avoid repeated progress announcements and unnecessary preambles.
- Communicate material decisions, tradeoffs, risks, blockers, and scope changes succinctly.
- Ask for clarification when missing information materially affects correctness and cannot be resolved reasonably from context.
- Explain destructive or consequential actions and seek approval when required.
- Provide deeper reasoning or explanation when the user requests it.
- At completion, concisely state what changed, what validation actually ran, and any unresolved issues.

These rules govern useful communication, not private reasoning or mandatory tool/runtime notices.
